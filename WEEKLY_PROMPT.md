Daily update for my CFB Matchup Dashboard — https://rhyman7.github.io/cfb/ (repo: github.com/rhyman7/cfb, branch main, served by GitHub Pages from the repo root).

**This is the daily run (every day at 9:47 AM ET, August–December).** It replaced the old Monday-only task. Each run: (a) rebuilds the data and publishes it if anything changed (new final scores from weeknight or weekend games, the week rolling over, line moves, AP poll); (b) reads injury designations for this week's games and publishes them as the site's injury tags; (c) checks the weather for upcoming outdoor games; then (d) tells me what's worth knowing. On quiet days with nothing to report, stay silent.

## Goal
Refresh `data/data.json` with current 2026 FBS regular-season stats and `data/injuries.json` with current injury designations, and push them to main so the live site updates. The site has these pages: `index.html` (this week's games), `edges.html` (Weekly Edges: game board and prop matchups), `matchup.html` (one game), `print.html` (prints every matchup), `dashboard.html` (compare any two teams), `ratings.html` (ratings explained), plus `epa.html`, `epa-explained.html` and `how-to-read.html`. Do not change the HTML files, any JS, `style.css` or the scripts unless a step below says to. (Live scores, box scores, the current ESPN line and the kickoff forecast are fetched by the viewer's browser at page load; this task never touches them. Weather goes only into my message; the site's forecast is live already.) The pages read `data/data.json`, so its shape must stay the same (see "data.json shape"). The week strip in the top bar also reads `data/season.json` and `data/weeks/<N>.json`; the build script writes those (and `data/epa.json`) on every run, so don't edit them by hand. The injury tags (an O/D/Q/P superscript after each listed player's name, and an Injury report on each team card) come from `data/injuries.json`, which `scripts/injuries.py` writes in step 7; don't edit it by hand either.

**Redesign (October 2026).** The site's look was redesigned (week board, scorebug game header, team-color blocks from `teamcolors.js`, Head to Head rank bars, Archivo type). It's merged into main and intentional, so never treat it as broken or restore older files over it. Newer features (the week strip, including its note when a week's matchups aren't set yet, the EPA pages and the injury tags) are intentional too.

**Scope:** all FBS teams, 2026 regular season only (ESPN season_type 2 — includes conference championship games and Army–Navy; excludes bowls and the CFP), completed games only. The build script enforces this and builds everything from scratch each run. The one deliberate exception, handled by the script: each week game's `lineOpen` (the line at the week's first build) is kept from the published file when it's the same season and week, so the site can show line movement.

## Steps
1. Attach the repo with push access and clone it. The tool is `add_repo` from the Claude Code Remote connector (full name `mcp__claude-code-remote__add_repo`). Scheduled runs often start with it hidden, so if it isn't in your tool list, load it with ToolSearch (query `select:mcp__claude-code-remote__add_repo`, or search for `add_repo`) before deciding it's missing. Call it with owner `rhyman7`, repo `cfb`, access `push`, then clone exactly as its result says. If add_repo returns an error, wait 30 seconds and try once more. (If a clone of rhyman7/cfb already exists in the working directory, `git pull` it and use it.) Before building, confirm you can push: run `git push --dry-run origin HEAD:main` in the clone. If you still can't attach or push, do the whole update anyway and then follow "If you can't push" below. Never end the run with only a note that the push failed.
2. Note what's published: `generatedAt`, `throughWeek`, `gamesCounted`, `currentWeek`, and each `weekGames` entry's `spread`, `total` and `lineOpen` in `data/data.json`. Keep a copy of the published file for comparison (step 6).
3. Build: `pip install --break-system-packages -r requirements.txt`, then `python scripts/build_data.py` from the repo root. Keep the default `--out` (the repo's `data/data.json`) so the script can read the published file for `lineOpen`. It downloads parquet files from `https://raw.githubusercontent.com/sportsdataverse/cfbfastR-cfb-data/main/cfb/` for 2026 (cfb_schedule, team_box, player_box, cfb_teams, cfb_rosters, cfb_matchup_line, play_by_play, game_rosters), plus the season schedule CSV from `https://raw.githubusercontent.com/sportsdataverse/cfbfastR-cfb-raw/main/cfb/schedules/csv/cfb_schedule_2026.csv` (upcoming games and AP ranks). No API key is needed. The shell can't reach collegefootballdata.com, ESPN or Sports-Reference, so don't try them from the shell. The script prints `note:` lines; pass on anything unusual in step 9. A note that positions were "filled from game_rosters" is normal (cfb_rosters was cut to 4 teams on 2026-09-29); so are "starting QBs for N teams applied from overrides/qb_starters.json" and, on the first run of a new week, "overrides/qb_starters.json is for Week N, not Week M: not applied" (step 7e writes the new week's list). A note that play-by-play or game_rosters failed to download means EPA/targets or the position fallback are missing: retry once, and if it's still missing publish anyway and tell me.
4. Decide whether to publish:
   - Compare the new `data/` files with what's published (`git diff --stat data` plus a check of `data/data.json` ignoring `generatedAt`). If nothing changed except `generatedAt`, don't commit or push: `git checkout -- data` and go on to step 7 (injuries) — there's no need to verify pages.
   - **Freshness (only on the first run after a Saturday slate — Sunday and Monday):** if the schedule has fewer than ~40 final games dated that Thursday–Saturday (in-season weeks usually have 60+), the source hasn't caught up. On Sunday, publish what's there (it'll fill in Monday). On Monday, wait about 2 hours and rebuild once; if it's still short, publish what's there and tell me which week it runs through.
   - If a download fails (404 or file missing), check the repo's file list with `git clone --depth 1 --filter=blob:none --no-checkout https://github.com/sportsdataverse/cfbfastR-cfb-data` (or `cfbfastR-cfb-raw` for the schedule CSV) and `git ls-tree -r --name-only HEAD | grep 2026`. If files were renamed or moved, update the paths in `FILES` at the top of `scripts/build_data.py`, rebuild, commit the script too, and tell me what changed. If the core data is gone entirely, stop and tell me.
   - If it's after December 15 and nothing new has come in, tell me the regular season looks finished so I can turn this scheduled task off.
5. Verify before pushing (write a short Python check; report any failure):
   - 130+ FBS teams; every team has at least one passer, rusher and receiver, and no player named "Team".
   - `currentWeek` is the coming week (the first regular-season week with unplayed games) and `weekGames` lists its games (normally 40–70; bye-heavy weeks and conference championship week are smaller; on Thursday–Saturday some may already be final). Every game has both teams, a start time, an id and a `lineOpen` object; FBS teams have a `key` that exists in `teams`. Most FBS-vs-FBS games have a `spread` and `total` and each FBS side has a `qb`. If `currentWeek` moved since the published file, `lineOpen` should equal each game's `spread`/`total` with today's date; if it's the same week, `lineOpen` must be unchanged from the published file.
   - Exactly 25 teams have an `apRank` (1–25, no duplicates), unless the poll isn't out yet; say so if not.
   - Ranks run from 1 up to about the team count; values sane (team rush yds/G 30–400, pass yds/G 50–450, PPG 3–70).
   - `gameLogs`: every row in every team's `passing`, `rushing` and `receiving` table has a `log` key that exists in `gameLogs` and a non-empty `pos`; `hasTargets` is true and log entries carry `tgt` for receivers.
   - `betting`: every team has it; league-wide ATS wins equal ATS losses; team-games in all `betting.games` lists = 2 × completed games that have a matchup line; for each team, fav+dog ≤ ats total and home+away ≤ ats total.
   - `eff`: every team has offense and defense `epa`, `sr` and ranks; EPA/play between −0.6 and 0.6, success rate 25–70.
   - Week strip files: `data/season.json` lists weeks 1–15 and every `data/weeks/<N>.json` exists; the file for the last finished week has every game `completed` with scores, and the file for `currentWeek` has the same games as `weekGames`.
   - When `throughWeek` or `currentWeek` changed (a new week), also do the full page check: run `python -m http.server 8000` and load the pages headlessly with Playwright (Chromium, at /opt/pw-browsers) at 1280 and 390 wide with no page errors (failed requests to ESPN and Open-Meteo are expected): `index.html` lists the week's games; one `matchup.html?game=<id>` for an FBS-vs-FBS game shows the game header (implied-totals line starting "Implied" and a line-move line), Head to Head with "EPA / play" and "Success %" rows, Betting Trends for both teams and two team cards (hover a player name — scroll it into view first, then move the mouse onto it — for the game-log tooltip; click it for the game-log panel); `dashboard.html`, `edges.html` (game board + QB/RB/WR/TE prop tables), `ratings.html` and `print.html?auto=0` load; `index.html?week=<finished week>` shows final scores linking to games. Top-bar search: two letters of a player's name, ArrowDown, Enter opens the game-log panel. On other days, just load `index.html` and one `matchup.html?game=<id>` to confirm no page errors.
6. Commit the `data` folder (`git add data`), plus the script if step 4 changed it, to main and push. Commit message: on a new week `Week N data update (through Week M, 2026)`; otherwise `Week N daily refresh (YYYY-MM-DD)` (N = currentWeek). Pages redeploys within a couple of minutes. Confirm it went live: WebFetch `https://rhyman7.github.io/cfb/data/data.json` and check the new `generatedAt`; if that isn't reachable, check the "pages build and deployment" run for your commit succeeded (`gh api "repos/rhyman7/cfb/actions/runs?per_page=3"`) and say that's how you confirmed it. Also note, for step 9: games that went final since the published file; and line moves since the published file (spread 1+ point or total 1.5+ points), plus any game whose spread crossed 3, 7 or 10 or flipped favorite since `lineOpen`.

Read each team's own Covers injuries page: `https://www.covers.com/sport/football/ncaaf/teams/main/<slug>/injuries`, using the verified slugs in the table at the end of this prompt (all 138 teams were checked on Oct 21, 2026; the same table is in the project doc `claude/covers-injury-urls.md`). Don't use the league page (https://www.covers.com/sport/football/ncaaf/injuries) for this: WebFetch only loads Air Force through about Colorado on it.       - To keep it fast, split the teams into about 5 equal groups and hand each group to a general-purpose subagent (Agent tool), all launched in the same message so they run in parallel (about 6 minutes for 106 teams with 4 groups).       - If a subagent's fetches fail (for example a permission timeout), read its unread teams yourself with WebFetch and add them to a JSON file of your own in the same shape. Any team still not read gets covered by step 7b and keeps its previous tags. Tell me about any corrected slug so the table can be updated.
   b. **News search (every run).** Use WebSearch (and WebFetch on the articles) for injury news from the last ~48 hours that Covers may not have yet, and for any team Covers couldn't be read for, prioritizing games in the next 4 days with an AP-ranked team, then games with a spread of 10 or less (on Sunday–Tuesday, starting QBs for the coming Saturday only): team beat writers, school releases, ESPN, The Athletic, On3, 247Sports, RotoWire, Action Network and similar. Check each article's date and ignore anything from a previous season (old articles often show up in results).

   e. **Starting QB for every team, every run.** Don't assume last week's starter: on every run, check who is expected to start at QB this week for every FBS team in `weekGames` that hasn't kicked off. ## data.json shape (keys the pages read; the script writes all of them)
- Top level: `generatedAt`, `season`, `throughWeek`, `gamesCounted`, `source`, `teamNames`, `teams`, `currentWeek`, `pollName`, `weekGames`, `gameLogs`, `hasTargets`, `notes`, `leagueAverage`, `gaugeRanges`.
- `teams[name]`: `team`, `conference`, `abbr`, `record` {w, l, t, sos, srs, osrs, dsrs}, `offense`, `defense`, `passing`/`rushing`/`receiving` rows (each with `player`, the table stats, `pos`, `log`), `defVsPosition` {rb, recRb, te, wr}, `apRank`, `betting` {ats, fav, dog, home, away: {w,l,p}, ou: {o,u,p}, games: [{w, opp, at, line, score, ats, total?, ou?}]} and `eff` {off, def: {epa, sr, passEpa, rushEpa, plays, epaRank, srRank}}.
- `weekGames[]`: `id`, `week`, `start`, `timeTbd`, `neutral`, `conferenceGame`, `status`, `statusDetail`, `completed`, `venue`, `city`, `tv`, `note`, `indoor`, `spread` (home side, negative = home favored), `total`, `away`/`home` {name, key, rank, record, conference, score, abbr, qb}, `lineOpen` {spread, total, at}.
- `gameLogs["ABBR|athlete_id"]`: one entry per game {w, opp, at?, res, cmp, att, pYds, pTd, int, car, rYds, rTd, rec, recYds, recTd, tgt}; zero stats are left out.
The build script is the source of truth for the shape; don't remove keys it writes.

## data/injuries.json shape (written by scripts/injuries.py)
`season`, `generatedAt`, `source`, `teamsRead`, `checked` {team name: date its Covers page was last read}, `players` {gameLogs key: {s (O/D/Q/P), status, injury, date, src ("Covers" or the news outlet), note ("Knee · Covers, Oct 17 · …"), name (as listed), player (site name), team, pos, stale?, playedSince?}}, `unmatched` [the same fields, for listed players who aren't in the site's stat tables]. The pages read `players`, `unmatched` and `checked`; the script is the source of truth.

Restore them from this repo's git history (`git log -- index.html` and check out the last good version) rather than rebuilding by hand. Then run the update above.
