Weekly update for my CFB Matchup Dashboard — https://rhyman7.github.io/cfb/ (repo: github.com/rhyman7/cfb, branch main, served by GitHub Pages from the repo root).

## Goal
Refresh `data/data.json` with current 2026 FBS regular-season stats and push it to main so the live site updates. The site has six pages: `index.html` (this week's games), `edges.html` (Weekly Edges: game board and prop matchups), `matchup.html` (one game), `print.html` (prints every matchup), `dashboard.html` (compare any two teams) and `ratings.html` (ratings explained). Do not change the HTML files, `app.js`, `live.js`, `weather.js`, `style.css` or `scripts/build_data.py` unless a step below says to. (Live scores, box scores, the current ESPN line and the forecast are fetched by the browser; this task never touches them.) The pages read only `data/data.json`, so its shape must stay the same (see "data.json shape").

**Scope:** all FBS teams, 2026 regular season only (ESPN season_type 2 — includes conference championship games and Army–Navy; excludes bowls and the CFP), completed games only. The build script enforces this and builds everything from scratch from the current season's files each run. The one deliberate exception, handled by the script: each week game's `lineOpen` (the line at the week's first build) is kept from the published file when it's the same season and week, so the site can show line movement.

## Steps
1. Attach the repo with push access (add_repo: owner `rhyman7`, repo `cfb`, access `push`) and clone it.
2. Note what's published: `generatedAt`, `throughWeek`, `gamesCounted` and `currentWeek` in `data/data.json`.
3. Build: `pip install --break-system-packages -r requirements.txt`, then `python scripts/build_data.py` from the repo root. Keep the default `--out` (the repo's `data/data.json`) so the script can read the published file for `lineOpen`. It downloads eight parquet files from `https://raw.githubusercontent.com/sportsdataverse/cfbfastR-cfb-data/main/cfb/` for 2026 (cfb_schedule, team_box, player_box, cfb_teams, cfb_rosters, cfb_matchup_line — spreads and O/U —, play_by_play — EPA, success rate, targets — and game_rosters — position fallback), plus the full season schedule CSV from `https://raw.githubusercontent.com/sportsdataverse/cfbfastR-cfb-raw/main/cfb/schedules/csv/cfb_schedule_2026.csv` (upcoming games and AP ranks). No API key is needed. The workspace can't reach collegefootballdata.com, ESPN or Sports-Reference, so don't try them. The script prints `note:` lines; pass them on to me in step 7. A note that positions were "filled from game_rosters" is normal when the source's cfb_rosters is incomplete (it was cut to 4 teams on 2026-09-29) — say how many teams cfb_rosters listed. A note that play-by-play or game_rosters failed to download means EPA/targets or the position fallback are missing: retry once, and if it's still missing publish anyway and tell me.
4. Decide whether to publish:
   - If the new `gamesCounted` equals the published one, no games have been added: stop and send me one line saying so. If it's after December 15 and nothing new has come in, also tell me the regular season looks finished so I can turn this scheduled task off.
   - Check freshness: find the most recent Saturday before today. If the schedule has fewer than ~40 final games dated that Thursday–Saturday (in-season weeks usually have 60+), the source probably hasn't caught up. Wait about 2 hours and rebuild once; if it's still short, publish what's there and tell me which week it runs through.
   - If a download fails (404 or file missing), check the repo's file list with `git clone --depth 1 --filter=blob:none --no-checkout https://github.com/sportsdataverse/cfbfastR-cfb-data` (or `cfbfastR-cfb-raw` for the schedule CSV) and `git ls-tree -r --name-only HEAD | grep 2026`. If files were renamed or moved, update the paths in `FILES` at the top of `scripts/build_data.py`, rebuild, commit the script too, and tell me what changed. If the core data is gone entirely, stop and tell me.
5. Verify before pushing (write a short Python check; report any failure):
   - 130+ FBS teams; every team has at least one passer, rusher and receiver, and no player named "Team".
   - `currentWeek` is the coming week (the first regular-season week with unplayed games) and `weekGames` lists its games (normally 40–70; bye-heavy weeks and conference championship week are smaller). Every game has both teams, a start time, a clickable id and a `lineOpen` object, and FBS teams have a `key` that exists in `teams`. Most FBS-vs-FBS games have a `spread` and `total` and each FBS side has a `qb`; if spreads are missing for the whole week, say so but still publish. On a new week, `lineOpen` should equal each game's `spread`/`total` with today's date; on a rerun of the same week, `lineOpen` must be unchanged from the published file.
   - Exactly 25 teams have an `apRank` (1–25, no duplicates), unless the poll isn't out yet; say so if not.
   - Ranks run from 1 up to about the team count; values sane (team rush yds/G 30–400, pass yds/G 50–450, PPG 3–70).
   - `gameLogs`: every row in every team's `passing`, `rushing` and `receiving` table has a `log` key that exists in `gameLogs` and a non-empty `pos`; for two players the number of log entries matches the games they appear in for that team. `hasTargets` is true and log entries carry `tgt` for receivers.
   - `betting`: every team has it; league-wide ATS wins equal ATS losses (sum of every team's `ats.w` = sum of `ats.l`); the number of team-games in all `betting.games` lists = 2 × completed games that have a matchup line; for each team, fav+dog ≤ ats total and home+away ≤ ats total. Recompute one game's ATS and O/U result by hand from the matchup line and final score.
   - `eff`: every team has offense and defense `epa`, `sr` and ranks; EPA/play between −0.6 and 0.6, success rate between 25 and 70, ranks 1 to the team count, and each offense's `plays` roughly 45–95 per game played (run + pass plays only).
   - W+L+T for two teams matches their final regular-season games in the schedule; spot-check one known starting QB's yards/G against the player box.
   - Run `python -m http.server 8000` and load the pages headlessly with Playwright (Chromium) at desktop (1280 wide) and phone (390 wide) widths, with no page errors (failed requests to ESPN and Open-Meteo are expected — the workspace can't reach them): `index.html` shows the week's game cards; one `matchup.html?game=<id>` for an FBS-vs-FBS game shows the game header (with an "Implied:" line and a line-move line), Head to Head with "EPA / play" and "Success %" rows, Betting Trends for both teams, and two team cards (hovering a player name shows the game-log tooltip, clicking it opens the game-log panel); `dashboard.html` shows two team cards and Betting Trends; `edges.html` shows the game board (one row per week game) and four prop tables (QB, RB, WR, TE); `ratings.html` and `print.html?auto=0` load. **Search:** on any page, type two letters of a known player's name into the top-bar search, press ArrowDown/ArrowUp and Enter, and check the game-log panel opens for that player. **Prop check:** in that panel, the prop result reads "Over X: N of M games", switching the stat changes the line and the "Next: …" opponent line, and the Prop column shows O/U tags. Also print one matchup page to PDF and confirm it's one page.
6. Commit only `data/data.json` (plus the script if step 4 changed it) to main with a message like `Week N data update (through Week N, 2026)` and push. Pages redeploys within a couple of minutes.
7. Send me a short message: which week the stats now run through, which week's games the landing page shows (and how many), the ATS balance (W = L), any `note:` lines, and anything that fell back or looked off. Nothing else.

## data.json shape (keys the pages read; the script writes all of them)
- Top level: `generatedAt`, `season`, `throughWeek`, `gamesCounted`, `source`, `teamNames`, `teams`, `currentWeek`, `pollName`, `weekGames`, `gameLogs`, `hasTargets`, `notes`, `leagueAverage`, `gaugeRanges`.
- `teams[name]`: `team`, `conference`, `abbr`, `record` {w, l, t, sos, srs, osrs, dsrs}, `offense`, `defense`, `passing`/`rushing`/`receiving` rows (each with `player`, the table stats, `pos`, `log`), `defVsPosition` {rb, recRb, te, wr}, `apRank`, `betting` {ats, fav, dog, home, away: {w,l,p}, ou: {o,u,p}, games: [{w, opp, at, line, score, ats, total?, ou?}]} and `eff` {off, def: {epa, sr, passEpa, rushEpa, plays, epaRank, srRank}}.
- `weekGames[]`: `id`, `week`, `start`, `timeTbd`, `neutral`, `conferenceGame`, `status`, `statusDetail`, `completed`, `venue`, `city`, `tv`, `note`, `indoor`, `spread` (home side, negative = home favored), `total`, `away`/`home` {name, key, rank, record, conference, score, abbr, qb}, `lineOpen` {spread, total, at}.
- `gameLogs["ABBR|athlete_id"]`: one entry per game {w, opp, at?, res, cmp, att, pYds, pTd, int, car, rYds, rTd, rec, recYds, recTd, tgt}; zero stats are left out.

## If the site files are missing
Restore them from this repo's git history (`git log -- index.html` and check out the last good version) rather than rebuilding by hand. Then run the update above.
